# QCAI audit of BlindSettlement

QoreChain's own AI auditor (QCAI, dashboard.qorechain.io/audit) reviewed `contracts/BlindSettlement.sol` on 22 Nov 2026. That is the source deployed at [`0xbdbd8fa8247a9bbc598f72cb46a2c7e3194ef3cf`](https://explore.qore.network/address/0xbdbd8fa8247a9bbc598f72cb46a2c7e3194ef3cf) on testnet.

**Result:** security score 72, risk level high, 6 findings. The full report is in [`qcai-report-2026-11-22.pdf`](qcai-report-2026-11-22.pdf).

We checked every finding against the code, and each answer below points at a test that proves it. Run them with `forge test --match-test qcai`. The whole suite is `forge test` (31 tests).

| # | QCAI finding | Severity | Our answer | Proof |
|---|---|---|---|---|
| 1 | Reentrancy in `_pull` and `_pay` | Critical | Not exploitable. Both are called only from `settle` and `withdraw`, which are both `nonReentrant`. Every order hash is marked used, and the batch is marked settled, before any token moves. | `test_qcai_reentryDuringSettleIsBlocked`: a hostile token re-enters `withdraw` mid settlement, holding a valid agent signature. The call fails and nothing leaves the contract. |
| 2 | Anyone can call `commit` | High | By design. A curve is only accepted with the market maker's ML-DSA-87 signature, checked on chain through the `pqcVerify` precompile. That signature is the access control, so it doesn't matter who sends the transaction. The contract also checks the curve's shape (it must slope the right way, with a positive size and a future expiry). | `test_drill_forgedQuoteRefused`, `test_curve_badShapeRefused`, `test_quoteCannotBeCommittedTwice` |
| 3 | Overflow in `_solve` | Medium | No wrong price is possible: Solidity 0.8 arithmetic is checked, so an overflow reverts instead of wrapping. We tested the range where no revert can happen at all. Prices go up to 2^48 (about 280 million fUSD per fETH). Maker size and batch totals go up to 2^72 (4,700 fETH). Real batches sit near 2^32 and 2^52. Anything outside that range reverts, and the operator retries the batch without the order that caused it. | `testFuzz_qcai_solveHasNoOverflowInRange`, 20,000 runs. `testFuzz_curve_priceIsTheFixedPoint` |
| 4 | Unchecked return values from external calls | Medium | Both checks are there: the call must succeed, and any returned bool must be true, otherwise `TransferFailed`. One true nuance: a call to an address with no code counts as a success. The two trading tokens are fixed at deploy and are real contracts. The only open path is `withdraw` of a made-up address, which needs the agent's signature and moves nothing. | Code: `_pull`, `_pay` |
| 5 | Unbounded loop in authentication | Low | Bounded: `MAX_ORDERS = 32`, checked before the loop starts. | `test_qcai_moreThan32OrdersRefused` |
| 6 | Front-running in order processing | Info | This is the problem Blind exists to solve. Orders are sealed until the market maker has committed its price. Every order in a batch fills at one price that the contract computes, so the order in which they are processed changes nothing. One limit stays: the operator holds the batch key and chooses which posted orders to settle. Any order it leaves out is listed with the reason on the proof page. | `test_drill_*`, live batches at https://blind.jdollar.site/proof |
